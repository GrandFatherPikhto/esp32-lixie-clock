# ⏰ Lixie-style Edge-Lit Clock on ESP32

Цифровые часы с «псевдоламповой» индикацией на основе светодиодной ленты WS2812 и сегментов из оргстекла (Edge-Lit / Lixie-подобные). В основе – ESP32, синхронизация времени по NTP через Wi-Fi, код написан на C для ESP-IDF v5.x. Все настройки можно менять **в рантайме через USB-порт платы** — без перепрошивки.

---

## ✨ Особенности

- Отображение времени (часы:минуты:секунды) на **6 разрядах** (настраивается в рантайме).
- Каждая цифра формируется из **10 светодиодов** (0…9) – зажигается нужная цифра в каждом разряде.
- Плавная смена цветов для каждой пары разрядов (часы, минуты, секунды) – вращение по цветовому кругу HSV (или фиксированный цвет).
- **Загрузочная анимация** (бегущие цифры 0…9) до первой успешной синхронизации времени.
- Автоматическая синхронизация времени по **NTP** с настраиваемым интервалом.
- **Настройка через USB в рантайме**: NTP-сервер, интервал синхронизации, часовой пояс, Wi-Fi SSID/пароль, яркость, количество разрядов, пин ленты, режим цвета — всё меняется с ПК через `configure_clock.py` и сохраняется в NVS.
- Сборка под все основные варианты ESP32 (`esp32`, `esp32-s2`, `esp32-s3`, `esp32-c3`, `esp32-c6`, `esp32-h2`).

---

## 🧩 Аппаратная часть

### Компоненты
- Плата ESP32 (любая, например, ESP32-DevKitC).
- Адресная светодиодная лента **WS2812** (или совместимая, например SK6812) – количество светодиодов = `разряды × 10`.
- 3D-печатные или лазерные сегменты с торцевой подсветкой (Edge-Lit) – по 10 светодиодов на цифру.

### Подключение

| ESP32 GPIO | Назначение         |
|------------|--------------------|
| **GPIO14** (по умолчанию) | DIN ленты WS2812  |
| 3.3V / 5V  | Питание ленты (учитывайте ток!) |
| GND        | Общий провод       |

> ⚠️ Убедитесь, что блок питания способен отдать достаточный ток (обычно ~60 мА на светодиод при полной яркости). Для 60 светодиодов – около 3.6 А при белом цвете. Рекомендуется внешний источник 5В/2А.

## ⚙️ Настройка

Есть два уровня настройки:

1. **Рантайм** (рекомендуется) – все рабочие параметры хранятся в NVS и меняются с ПК через USB-порт платы, без перепрошивки.
2. **Значения по умолчанию при сборке** – начальные значения (через `menuconfig`), действующие при первом запуске.

### 1️⃣ Настройка в рантайме (консоль / Python-инструмент)

Прошивка запускает интерактивную консоль (ESP Console) на **UART0** (USB-serial мост платы, 115200 бод) с приглашением `clock> `. Работать с ней можно из любого терминала или через готовый инструмент:

```bash
# Прочитать текущую конфигурацию
python tools/configure_clock.py get

# Задать несколько параметров (применяется сразу; SSID/пароль нужны для Wi-Fi)
python tools/configure_clock.py set ssid=MyWiFi password=secret ntp_server=pool.ntp.org

# Сохранить во flash (NVS) и перезагрузиться (reboot применяет gpio/digits)
python tools/configure_clock.py save
python tools/configure_clock.py reboot

# Показать статус Wi-Fi / синхронизации / дисплея
python tools/configure_clock.py status
```

Требуются `pyserial` и `pyyaml` (`pip install -r tools/requirements.txt`; либо используйте `.venv` проекта, см. ниже). Порт определяется автоматически; при необходимости укажите `--port COM5`.

**Доступные параметры** (`set key=value`):

| Ключ | Описание | По умолчанию |
|------|----------|--------------|
| `ntp_server` | Имя NTP-сервера | `pool.ntp.org` |
| `sync_interval` | Период синхронизации NTP, сек (30..604800) | `3600` |
| `tz_offset` | Смещение от UTC в минутах, напр. `180` = UTC+3 (Москва) | `180` |
| `ssid` | Имя Wi-Fi сети | *(пусто — нужно задать)* |
| `password` | Пароль Wi-Fi | *(пусто)* |
| `brightness` | Яркость ленты, проценты (0..100) | `100` |
| `digits` | Количество отображаемых разрядов (1..макс) | `6` |
| `gpio` | Пин ленты WS2812 *(применяется после перезагрузки)* | `14` |
| `color_mode` | `0` = вращение цвета, `1` = фиксированный цвет | `0` |
| `hue` | Фиксированный оттенок 0..359 (при `color_mode=1`) | `200` |
| `sync_method` | `0` = мгновенная, `1` = плавная (adjtime) | `0` |

Команды консоли: `get`, `set`, `save`, `reset`, `reboot`, `status`, `help`.

#### YAML-конфигурация (`config.yaml`)

В корне проекта лежит файл [`config.yaml`](config.yaml) — единый источник настроек для устройства; раздел `build:` также читает [`build_target.py`](tools/build_target.py). Верхнеуровневые ключи совпадают 1:1 с ключами `set` из таблицы выше.

```bash
# Применить всё из config.yaml, сохранить в NVS и перезагрузиться
python tools/configure_clock.py apply --save --reboot

# Использовать другой файл
python tools/configure_clock.py --config my_settings.yaml apply
```

Отредактируйте `config.yaml` перед прошивкой/запуском. Так как в нём могут быть реальные учётные данные Wi-Fi, при необходимости не коммитьте его в репозиторий (или храните учётные данные в отдельном игнорируемом файле).

> ⚠️ **SSID и пароль Wi-Fi теперь задаются здесь, а не в `menuconfig`.** Пока `ssid` не задан, часы показывают загрузочную анимацию и автоматически повторяют попытки подключения.

### 2️⃣ Значения по умолчанию (`menuconfig`)

Если используется только рантайм-инструмент, `menuconfig` не нужен. Начальные **значения по умолчанию** находятся в разделе **`Clock Configuration`**:

| Параметр | Описание |
|----------|----------|
| `GPIO number for LED strip (default)` | Начальный пин ленты (по умолчанию 14). |
| `Number of digit displays (default)` | Начальное количество разрядов (по умолчанию 6). |
| `Maximum number of digit displays` | Размер буфера пикселей при сборке; рантайм-`digits` ограничивается им. |
| `SNTP server name (default)` | Начальный NTP-сервер. |
| `Time synchronization method (default)` | `immediate` или `smooth`. |
| `Time synchronization period (default)` | Начальный интервал в секундах. |
| `Timezone offset (minutes from UTC, default)` | Начальный часовой пояс, напр. 180 = UTC+3. |
| `Default LED brightness (percent)` | Начальная яркость. |
| `Default color mode` / `Default fixed hue` | Начальные настройки цвета. |

```bash
idf.py menuconfig
```

## 🌐 Как работает синхронизация времени

1. **При старте** загружается конфигурация, устанавливается Wi-Fi-соединение (по заданным SSID/паролю) и отправляется запрос к NTP-серверу.
2. **После первого успешного ответа** системное время устанавливается, и флаг `time_is_synced()` становится `true`.
3. **Дисплей** переключается с загрузочной анимации на отображение текущего времени.
4. **Каждый заданный интервал** (по умолчанию 1 час) ESP32 повторно опрашивает NTP-сервер и корректирует время — Wi-Fi остаётся подключённым, переподключение не требуется.
5. **Если Wi-Fi/NTP недоступен**, часы продолжают показывать анимацию и повторяют попытку каждые 10 секунд до успеха.

> Если интернет временно недоступен *после* успешной синхронизации, часы продолжат отображать время, используя встроенный RTC (реального времени на ESP32 нет, поэтому время будет дрейфовать до следующей успешной синхронизации).

## ✅ Проверка настроек после сборки

После прошивки в мониторе (`idf.py monitor`) вы увидите:

```
I (xxxx) wifi_mgr: Got IP: 192.168.1.xx
I (xxxx) sntp_sync: Time synchronized successfully
I (xxxx) main: Time sync completed, sync task will exit
```

Также можно подключиться к последовательной консоли (115200 бод) и выполнить `status` или `get`.

Если синхронизация не происходит, проверьте:
- заданы и сохранены `ssid` / `password` (`configure_clock.py set ssid=... password=... save`);
- доступность NTP-сервера в вашей сети (пинг с компьютера);
- не блокирует ли роутер NTP-трафик (порт 123 UDP).

## 🛠️ Сборка и прошивка

1. Установите ESP-IDF (рекомендуется версия 5.3 или 5.5.3).
2. Скопируйте файлы проекта в папку.
3. Активируйте окружение IDF:
   ```bash
   . $HOME/esp/esp-idf/export.sh   # Linux/macOS
   .\export.ps1                    # Windows (PowerShell)
   ```
4. При необходимости задайте значения по умолчанию: `idf.py menuconfig`.
5. Соберите (при необходимости под конкретный чип) и прошейте:

   ```bash
   # Одной командой для любого поддерживаемого чипа:
   python tools/build_target.py --target esp32s3 --flash
   # или вручную:
   idf.py set-target esp32s3
   idf.py build
   idf.py flash monitor
   ```

   `build_target.py` также читает раздел `build:` из [`config.yaml`](config.yaml), когда флаги не указаны:
   ```bash
   python tools/build_target.py --config config.yaml
   ```

6. Настройте Wi-Fi и параметры через USB:
   ```bash
   python tools/configure_clock.py set ssid=MyWiFi password=secret save reboot
   # или из YAML-файла:
   python tools/configure_clock.py apply --save --reboot
   ```

### 🐍 Python-виртуальное окружение (рекомендуется)

Создайте `.venv` в корне проекта (он уже добавлен в `.gitignore`):

```bash
python -m venv .venv
.venv\Scripts\activate            # Windows
source .venv/bin/activate         # Linux/macOS
pip install -r tools/requirements.txt
```

Затем запускайте инструменты `python tools/configure_clock.py ...` и `python tools/build_target.py ...` при активном venv.

### 🧪 Тесты (Python-инструменты — плата не нужна)

[`configure_clock.py`](tools/configure_clock.py) и [`build_target.py`](tools/build_target.py) покрыты набором тестов pytest в [`tests/`](tests/): последовательный порт и YAML-файлы мокаются, поэтому **плата ESP32 не требуется**. Запуск из корня проекта:

```bash
.venv\Scripts\python -m pytest tests -v   # Windows
.venv/bin/python -m pytest tests -v       # Linux/macOS
```

`pytest` объявлен в [`tools/requirements.txt`](tools/requirements.txt) — при необходимости установите через `pip install -r tools/requirements.txt`.

### 🛠️ Host C unit-тесты (Уровень 2 — чистая логика, без платы, нужен Linux/WSL)

Чистая логика прошивки вынесена в [`core/`](core/) (разбор/валидация конфигурации, математика часового пояса, отрисовка цифр) **без зависимостей от ESP-IDF**, поэтому её можно тестировать нативно на Linux-хосте через Unity. Host-тесты работают только на Linux — запускайте их из **WSL2**:

1. Откройте терминал WSL (Windows Terminal или `wsl -d Ubuntu-24.04`).
2. Активируйте окружение ESP-IDF установки IDF внутри WSL (здесь v6.0):
   ```bash
   . /home/grand/esp/esp-idf-v6.0/export.sh
   ```
3. Перейдите в проект — из WSL Windows-папка смонтирована в `/mnt/d`:
   ```bash
   cd /mnt/d/Projects/Espressif/Clock/clock
   ```
4. Соберите и запустите host-тесты:
   ```bash
   bash tests/c/run_tests.sh
   ```

Скрипт собирает `core/src/*.c` + Unity (из `$IDF_PATH`) + [`tests/c/test_core.c`](tests/c/test_core.c) в `build_host/` и запускает. Ожидаемый результат:

```
14 Tests 0 Failures 0 Ignored
OK
```

Покрываются именно те функции, которые использует прошивка (`core_config_set_value`, `core_time_format_tz`, `core_display_set_digit`, ...).

Прошивка не привязана к конкретному чипу — достаточно, чтобы пин ленты соответствовал вашей разводке.

## 🧱 Архитектура кода

Проект разделён на логические модули для упрощения поддержки и модификации:

| Модуль | Назначение |
|--------|------------|
| **`app_config`** | Рантайм-конфигурация в NVS (Wi-Fi, NTP, часовой пояс, яркость, разряды, GPIO, цвет). Функции `get`/`set`/`save`/`reset` и геттеры для остальных модулей. |
| **`config_console`** | REPL-консоль ESP Console на UART0 (USB). Команды `get`, `set`, `save`, `reset`, `reboot`, `status`. |
| **`wifi_manager`** | Подключение к Wi-Fi по SSID/паролю из конфигурации, авто-переподключение, ожидание IP. |
| **`led_display`** | Инициализация RMT-канала и энкодера, `led_display_send()` для отправки буферов пикселей. |
| **`clock_ui`** | Формирование кадров: HSV→RGB, установка цифр, яркость/цвет. `clock_ui_fill_time()` и `clock_ui_fill_animation()` рендерят в буфер, переданный вызывающим кодом. |
| **`sntp_sync`** | Инициализация SNTP по рантайм-настройкам, ожидание первой синхронизации, флаг статуса. |
| **`led_strip_encoder`** | Специфичный для WS2812 RMT-энкодер. |
| **`main`** | Запуск и задачи FreeRTOS: `sync_task` и `display_task`. |

### Задачи FreeRTOS
- **`sync_task`** (приоритет 5) – подключает Wi-Fi и вызывает `init_sntp()`; при успехе ставит флаг синхронизации и завершается; при неудаче повторяет каждые 10 с.
- **`display_task`** (приоритет 4) – цикл каждые 500 мс. До синхронизации: анимация; после: текущее время. Владеет буфером пикселей.

## 📦 Основные функции

| Функция | Описание |
|---------|----------|
| `app_config_init()` | Загружает конфигурацию из NVS (или значения по умолчанию) и применяет часовой пояс. |
| `app_config_set/save/reset()` | Изменение, сохранение и сброс рантайм-конфигурации. |
| `config_console_init()` | Запуск консольной REPL с командами конфигурации. |
| `wifi_manager_connect()` | Подключение к настроенной Wi-Fi и ожидание IP (повторяет в фоне). |
| `led_display_init()` | Инициализация RMT + энкодера с использованием рантайм-пина ленты. |
| `led_display_send(pixels, size)` | Отправка массива пикселей на ленту (блокирующий вызов). |
| `clock_ui_fill_time(pixels)` | Рендер текущего времени в буфер. |
| `clock_ui_fill_animation(pixels)` | Рендер загрузочной анимации в буфер. |
| `init_sntp()` | Подключение, запуск SNTP и ожидание первой синхронизации; возвращает успех. |
| `time_is_synced()` | `true` только после успешной синхронизации времени. |

## 🔧 Зависимости

- **`console`** – компонент ESP-IDF, предоставляющий интерактивную REPL (`esp_console`).
- Остальные компоненты (драйвер RMT, SNTP, NVS, Wi-Fi, FreeRTOS) входят в состав ESP-IDF.

Прежняя зависимость от `protocol_examples_common` удалена — Wi-Fi теперь обрабатывается собственным `wifi_manager`, чтобы SSID и пароль можно было настраивать в рантайме.
